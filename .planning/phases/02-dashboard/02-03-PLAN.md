    1. Add `GET /licenses/table` endpoint to `app/routers/pages.py` (per D-12). Add this AFTER the existing `index()` route. Import `Query` and `Optional` from fastapi/typing:

    ```python
    from fastapi import APIRouter, Request, Query
    from typing import Optional

    @router.get("/licenses/table", response_class=HTMLResponse)
    def license_table(
        request: Request,
        db: SessionDep,
        product: Optional[str] = Query(None),
        status: Optional[str] = Query(None),
        sort: str = Query("expiry_date"),
        order: str = Query("asc"),
    ):
        global_threshold = get_global_threshold(db)
        query = db.query(License)

        # Filter by product name — case-insensitive LIKE (per D-09)
        if product:
            query = query.filter(License.product_name.ilike(f"%{product}%"))

        licenses = query.all()
        enriched = enrich_licenses(licenses, global_threshold)

        # Filter by computed status (per D-09)
        if status:
            enriched = [e for e in enriched if e["status"] == status]

        # Sort (per D-10)
        sort_key_map = {
            "expiry_date": lambda e: e["license"].expiry_date,
            "product_name": lambda e: e["license"].product_name.lower(),
        }
        sort_fn = sort_key_map.get(sort, sort_key_map["expiry_date"])
        enriched.sort(key=sort_fn, reverse=(order == "desc"))

        return templates.TemplateResponse(
            request=request,
            name="partials/license_table.html",
            context={
                "licenses": enriched,
                "current_sort": sort,
                "current_order": order,
            },
        )
    ```

    Note: Use `sync def` (not async def) per CLAUDE.md convention.

    4. Also update the sort hidden inputs when HTMX swaps tbody — add `hx-swap-oob` or simply let the sort headers use query params directly. The hidden inputs track current sort state for filter requests. After an HTMX sort response, the sort/order hidden values should update. Handle this by having the partial endpoint also swap the hidden inputs via `hx-swap-oob`, OR by encoding sort state in the sort header URLs and having filters always include the hidden inputs.

    Simpler approach: When sort headers fire, they include their own sort/order in the URL params and include filter values via hx-include. The hidden sort/order inputs need to update after sort — add a small script block or use `hx-on::after-request` to update hidden values. Simplest: use `hx-vals` on sort headers instead of URL params, and update hidden inputs via oob swap in the partial response.

    SIMPLEST approach (recommended): Do NOT use hidden inputs for sort state. Instead, have the sort headers use `hx-get` with explicit sort params in the URL, and `hx-include` the filter inputs. The filter inputs use `hx-include` for the sort hidden inputs. Keep the hidden inputs as the "current sort state" tracker, and when a sort header is clicked, it sends the toggled sort/order directly in the URL (overriding hidden input values since URL params take precedence when duplicated — but to be safe, do NOT hx-include sort/order from hidden inputs in sort header requests).

    Final implementation:
    - Filter controls: `hx-include="[name='status'],[name='sort'],[name='order']"` (for product input) and `hx-include="[name='product'],[name='sort'],[name='order']"` (for status select)
    - Sort headers: `hx-include="[name='product'],[name='status']"` (only filter values, sort is in the URL)
    - Hidden inputs for sort/order: Updated by a small inline script that reads the `HX-Current-URL` or by accepting that sort state resets on filter. For v1, this is acceptable — sort state tracking via hidden inputs is good enough because the page starts fresh on full reload.
