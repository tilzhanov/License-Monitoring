# Phase 03.1 — UI Design Contract

> Retrofit contract for the License Monitoring Dashboard. Transforms the raw browser-default UI from Phases 1–3 into a polished, data-first internal ops dashboard (Linear / Grafana / Vercel aesthetic) without touching FastAPI routes, HTMX attributes, or Jinja2 template structure beyond class-name and copy changes.
>
> **Scope rule for the executor:** this phase is CSS-first. The only allowed Python/Jinja edits are (a) adding the Google Fonts `<link>` to `base.html`, (b) adding a single SVG sprite or inline icons, (c) swapping class names on existing elements, (d) wrapping/restructuring layout containers. All `hx-*` attributes, route URLs, and form field names MUST be preserved verbatim — Phase 2/3 integration tests depend on them.

## Spacing Scale

Declared values (multiples of 4, 8-point scale). CSS custom properties named `--space-*`.

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px  | Icon-to-text gap, badge inner padding Y |
| `--space-2` | 8px  | Form label-to-input gap, button icon gap, tight inline spacing |
| `--space-3` | 12px | Table cell vertical padding, input vertical padding |
| `--space-4` | 16px | Default element gap, form group margin, card inner padding Y |
| `--space-5` | 24px | Section padding, card inner padding X on desktop, form group margin between groups |
| `--space-6` | 32px | Gap between major sections (stats grid → table), page horizontal padding |
| `--space-8` | 48px | Top of page → first element, empty-state vertical padding |
| `--space-10` | 64px | 404 / hard-empty-state vertical padding |

**Exceptions:** `12px` (`--space-3`) is added because table row compact density requires it (between `--space-2=8` and `--space-4=16`). This is still a multiple of 4. No other exceptions.

**Touch targets:** all interactive elements (`.btn`, `.action-btn`, table header sort buttons, filter controls) MUST have a min-height of 32px AND `padding` such that the clickable hit area ≥ 32×32 (compact desktop-first internal tool — SKILL `touch-target-size` allows 32px on mouse-driven desktop; the 44px rule is for touch-first mobile, which this tool is not).

## Typography

Exactly **4 sizes**, **3 weights** (400/500/600 — 700 reserved only for `<strong>` inside detail body if needed; not counted as a "token" weight).

| Role | Size | Weight | Line Height | Used On |
|------|------|--------|-------------|---------|
| Label / caption | 12px | 500 | 1.4 | Table headers, form labels, breadcrumbs, stat-card labels, column headers, badge text |
| Body | 14px | 400 | 1.5 | Table cells, paragraphs, form input text, button text, navigation links |
| Heading (h2/h3) | 18px | 600 | 1.3 | Section headings ("Скоро истекающие", "Все лицензии"), detail card title, form card title |
| Display (h1) | 24px | 600 | 1.25 | Page title ("Мониторинг лицензий"), detail page product name, form page title |

**Tokens:**
```
--font-sans: "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
--font-mono: "JetBrains Mono", ui-monospace, "SF Mono", Menlo, Consolas, monospace;
--text-xs: 12px;
--text-sm: 14px;
--text-lg: 18px;
--text-xl: 24px;
--lh-tight: 1.25;
--lh-heading: 1.3;
--lh-label: 1.4;
--lh-body: 1.5;
--fw-regular: 400;
--fw-medium: 500;
--fw-semibold: 600;
```

**Tabular numbers (MANDATORY):** apply `font-variant-numeric: tabular-nums` to:
- `.license-table td` (all cells that hold dates or numbers)
- `.stat-card .count`
- `.days-badge`
- `.detail-value` containing dates
This prevents column jitter when values change (SKILL `number-tabular`).

**Color-not-only rule (SKILL `color-not-only`):** row background color is paired with (a) a 4px left border in the stronger status shade, (b) a text badge in the status column (already present: "Активна" / "Скоро истекает" / "Истекла"), and (c) a small inline SVG icon inside the badge (`check-circle-2` / `alert-triangle` / `x-circle`). A colorblind operator must be able to read status from the badge alone.

### 60/30/10 split declaration

- **60% dominant:** `--slate-50` page background + `--slate-100` hover zones
- **30% secondary:** `--surface` (white) cards, table, form containers + `--slate-900` top nav
- **10% accent:** `--accent-600` on primary CTA, focus ring, active sort, current-nav indicator — **nowhere else**

### Border-radius scale

| Token | Value | Usage |
|-------|-------|-------|
| `--radius-sm` | 4px  | Inputs, buttons, badges, filter controls |
| `--radius-md` | 6px  | Cards (stat-card, form-card, detail-card, expiring-widget), table outer container |
| `--radius-lg` | 999px | Pill badges only (days-badge, status-badge) |

No larger radius. No asymmetric radius.

### Shadow scale (subtle — borders do most of the work)

| Token | Value | Usage |
|-------|-------|-------|
| `--shadow-none` | `none` | Default (everything relies on 1px border) |
| `--shadow-sm` | `0 1px 2px 0 rgba(15, 23, 42, 0.04)` | Stat cards, form card, detail card (optional secondary layer under border) |
| `--shadow-focus` | `0 0 0 3px rgba(37, 99, 235, 0.25)` | Focus ring (accent-600 at 25% alpha) |

Shadows are NEVER used to communicate hierarchy alone — always paired with a 1px `--slate-200` border (SKILL `elevation-consistent`).

### 3. Stat counter cards (`.stats-grid > .stat-card`)

- Grid: `grid-template-columns: repeat(3, 1fr)`, gap `--space-4` (16px), margin-bottom `--space-6`
- Card: `background: --surface`, `border: 1px solid --slate-200`, `border-radius: --radius-md`, padding `--space-5` (24px), no shadow by default
- **Label first, then count** (inverted from current order — ops dashboard convention, Linear-style): label is 12px `--slate-500` uppercase letter-spacing 0.04em; count is 28px weight 600 tabular-nums, color based on variant

### 4. Expiring Soon widget (`.expiring-widget`)

- Card styling identical to stat-card (border, radius, padding, surface, shadow-sm)

- Empty state: `<p>Нет лицензий, требующих внимания</p>` → 14px `--slate-500`, italic OFF

### 5. License table (`.license-table`)

- Container: wrap in `<div class="table-container">` with `background: --surface`, `border: 1px solid --slate-200`, `border-radius: --radius-md`, `overflow: hidden` (so row borders don't escape the radius)
- `<thead>`: background `--slate-50` (NOT `--slate-900` — the dark header from current CSS is too heavy for Linear style), `th` text 12px weight 500 uppercase letter-spacing 0.04em color `--slate-500`, padding `--space-3 --space-4`, `border-bottom: 1px solid --slate-200`, `text-align: left`

- Last row `td`: no border-bottom
- **Row coloring (DASH-03):**
  - `.status-active` → `background: --status-active-bg`, `box-shadow: inset 4px 0 0 0 --status-active-bar`
  - `.status-warning` → `background: --status-warning-bg`, `box-shadow: inset 4px 0 0 0 --status-warning-bar`

- Product name cell is a link: `color: --slate-900`, `font-weight: 500`, hover `color: --accent-600` + underline
- The "Статус" text column is replaced by a `.status-badge` pill (icon + label), because row color + 4px bar + badge together satisfy `color-not-only`

## Interaction Contracts (HTMX)

The executor MUST preserve all `hx-*` attributes. These contracts describe how the swaps should FEEL visually, implemented purely in CSS.

### Global HTMX indicators

Add to CSS:
```
.htmx-request { opacity: 0.6; transition: opacity 120ms ease-out; }
.htmx-request.htmx-indicator { opacity: 1; }
```

Add a subtle 2px progress bar at the top of `<main>` via `.htmx-indicator` — OR just use opacity fade on the swapped target. Pick opacity fade (simpler, no extra DOM).

### Table filter/sort (DASH-04)

- Target `#license-tbody` gets `.htmx-request` during swap → opacity 0.6, `pointer-events: none`
- On swap complete: new `<tr>` elements fade in via CSS `animation: fadeIn 120ms ease-out` keyframe (opacity 0 → 1). No layout shift since row height is fixed by padding.
- Active sort column header shows `chevron-up`/`chevron-down` SVG next to label; inactive columns show no icon
- Search input debounce is already 300ms (keep) — during that window the table is NOT in loading state (debounce, not request)

### Row delete

- `hx-confirm` native browser confirm stays (internal tool, no design budget for custom modal in this phase)
- On confirm → row gets `opacity: 0.4`, `transition: opacity 150ms`, then swap happens
- After swap, trigger `license-changed` on body (already wired) to refresh stats
- Stats refresh: `#stats-section` fades using opacity transition

### Form submission / validation

- Submit button shows `.htmx-request` state → opacity 0.6, `cursor: wait`, but stays enabled visually (HTMX disables via `hx-disabled-elt` if wired — executor decides)
- Field errors appear inline via `.field-error` block, color-coded red with icon, no layout jump (reserve space is NOT required since errors push content down naturally; acceptable for form)
- Inline edit (if 03-01 implemented edit-row fragment): the old row is replaced by an editable row with input fields matching the visual language of `.form-group` inputs but compressed to 32px height

### Hover/press feedback

- All buttons: background transitions 120ms ease-out
- Table rows: background transitions 120ms
- Links: color transitions 120ms
- `@media (prefers-reduced-motion: reduce)`: all transitions `duration: 0.01ms` (SKILL `reduced-motion`)

### Keyboard navigation

- Tab order follows visual order (no `tabindex` overrides)
- All interactive elements have `:focus-visible` outline (accent-600 2px + shadow-focus)
- Skip-link at top of body: `<a href="#main" class="skip-link">Перейти к содержимому</a>`, visually hidden until focus, then pinned top-left with `--accent-600` background and white text
- Sortable `<th>` gets `role="button"` and `tabindex="0"` (current implementation is pointer-only — this is a REQUIRED change for a11y)
