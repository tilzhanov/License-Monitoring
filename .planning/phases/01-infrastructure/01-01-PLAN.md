**`Dockerfile`:**
```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app/ ./app/
COPY templates/ ./templates/
COPY static/ ./static/

RUN mkdir -p /data

EXPOSE 8000

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

Key points per decisions:
- Internal port is 8000 (uvicorn default). Host port mapping is in docker-compose.yml.
- `RUN mkdir -p /data` ensures the volume mount point exists.
- COPY order: requirements first (layer caching), then app code.

**`docker-compose.yml`** (per D-01, D-02, D-03; no `version:` key per Pitfall 5):
```yaml
services:
  web:
    build: .
    ports:
      - "${APP_PORT:-8080}:8000"
    volumes:
      - licenses_db:/data
    env_file:
      - .env
    environment:
      - DB_PATH=/data/licenses.db
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 10s

volumes:
  licenses_db:
    driver: local
```

Key points:
- D-01: `${APP_PORT:-8080}:8000` -- host port configurable, internal fixed at 8000.
- D-02: `restart: unless-stopped`.
- D-03: Named volume `licenses_db` (not bind-mount).
- `DB_PATH=/data/licenses.db` hardcoded in environment (not just .env) per Pitfall 2.
- Healthcheck uses python urllib (no curl in slim image).

**`.env.example`** (per D-01, D-09):
```bash
# Application port (host-side)
APP_PORT=8080

# Database path (inside container, matches volume mount)
DB_PATH=/data/licenses.db

# Telegram bot credentials (bootstrap only -- DB takes priority after first run)

TELEGRAM_CHAT_ID=

# Global notification threshold in days (bootstrap default)
NOTIFY_DAYS_BEFORE=60

# SQL query logging (true/false)

```

This task does NOT attempt to build the image -- the app code (`app/main.py`) does not exist yet. Build verification happens in Plan 01-03.
